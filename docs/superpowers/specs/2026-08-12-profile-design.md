# Profile — Design Spec

วันที่: 2026-08-12
สถานะ: อนุมัติแล้ว รอเขียน implementation plan

## เป้าหมาย

ฟีเจอร์แรกของ `null-app` — ระบบโปรไฟล์พื้นฐานที่ผู้ใช้กรอกชื่อและคำแนะนำตัวสั้น ๆ เก็บไว้ในเครื่อง
พร้อมหน้า Home ที่ยังว่างและมีปุ่มเดียวสำหรับเข้าไปดูโปรไฟล์

นอกจากตัวฟีเจอร์เอง งานรอบนี้ทำหน้าที่วางโครงของแอปด้วย: navigation, การแยก state ออกจาก view,
การเก็บข้อมูลลงดิสก์ และการจัดการ error — เพื่อให้ฟีเจอร์ถัดไปต่อยอดได้โดยไม่ต้องรื้อ

## ขอบเขต

อยู่ในขอบเขต:

- หน้า Home ว่าง มีปุ่มไปหน้า Profile
- หน้า Profile แสดงชื่อ, bio, และวงกลมอักษรย่อ
- หน้าแก้ไขโปรไฟล์แบบ sheet พร้อม Save / Cancel
- เก็บข้อมูลเป็นไฟล์ JSON ในเครื่อง
- ทำงานได้ทั้ง iOS, iPadOS, macOS, visionOS

ไม่อยู่ในขอบเขต (ตัดออกโดยตั้งใจ):

- รูปโปรไฟล์จากคลังภาพ — ใช้อักษรย่อไปก่อน
- login, backend, การ sync ข้ามเครื่อง
- โปรไฟล์หลายอัน — ระบบนี้มีโปรไฟล์เดียวเสมอ
- automated test — ดูหัวข้อ "Test" ด้านล่างสำหรับเหตุผลและทางออก

## สถาปัตยกรรม

`ProfileStore` เป็นเจ้าของ state เพียงผู้เดียว ส่งให้ View ผ่าน SwiftUI environment
View ไม่แตะไฟล์เองและไม่เก็บ state ถาวรของตัวเอง

```
null_appApp
  └── NavigationStack
        └── HomeView ──(ปุ่ม)──> ProfileView ──(sheet)──> ProfileEditView
                                      │                        │
                                      │      ส่ง Profile ที่แก้แล้วกลับมา
                                      │      ผ่าน closure ◄────┘
                                      │
                                 ProfileStore
                                      │
                                 profile.json
```

### ไฟล์ที่จะสร้าง

| ไฟล์ | หน้าที่ |
|---|---|
| `Models/Profile.swift` | struct ข้อมูลโปรไฟล์ + กฎการสร้างอักษรย่อ + กฎ validation |
| `Storage/ProfileStore.swift` | `@Observable` ถือ state ปัจจุบัน, load/save ลงดิสก์ |
| `Views/HomeView.swift` | หน้าแรก ว่าง มีปุ่มเดียว |
| `Views/ProfileView.swift` | แสดงโปรไฟล์ + ปุ่ม Edit + alert ตอน save พลาด |
| `Views/ProfileEditView.swift` | ฟอร์มแก้ไขบน sheet |
| `Views/InitialsAvatar.swift` | วงกลมอักษรย่อ ใช้ซ้ำได้ |

ไฟล์ที่แก้: `null_appApp.swift` (วาง `NavigationStack`, สร้างและ inject store)
`ContentView.swift` จะถูกลบ เพราะ `HomeView` มาแทนที่

เหตุผลที่แยก `InitialsAvatar` ออกมา: ถูกใช้ทั้งในหน้าแสดงผลและหน้าแก้ไข และเป็นจุดเดียวที่ต้องแก้
เมื่อวันหนึ่งเปลี่ยนไปใช้รูปจริง

## Data model

```swift
struct Profile: Codable, Equatable, Sendable {
    var displayName: String
    var bio: String
}
```

ค่าเริ่มต้นเมื่อยังไม่เคยตั้งค่า: ทั้งสองฟิลด์เป็นสตริงว่าง

### กฎการสร้างอักษรย่อ

คำนวณจาก `displayName` เป็น computed property:

1. ตัดช่องว่างหัวท้าย แล้วแยกคำด้วยช่องว่าง ทิ้งคำว่างออก
2. เอาอักษรตัวแรกของคำแรก และอักษรตัวแรกของคำที่สอง (ถ้ามี)
3. แปลงเป็นตัวพิมพ์ใหญ่
4. ถ้าไม่เหลือคำใดเลย คืนค่า `"?"`

ตัวอย่าง: `"Purin Tae"` → `"PT"` / `"purin"` → `"P"` / `""` → `"?"` / `"  "` → `"?"`

### กฎ validation

| ฟิลด์ | กฎ | บังคับใช้อย่างไร |
|---|---|---|
| `displayName` | ตัดช่องว่างหัวท้ายแล้วต้องไม่ว่าง และยาวไม่เกิน 50 ตัวอักษร | ปุ่ม Save เป็น disabled เมื่อไม่ผ่าน |
| `bio` | ไม่บังคับกรอก ยาวไม่เกิน 160 ตัวอักษร | ปุ่ม Save เป็น disabled เมื่อเกิน และแสดงตัวนับจำนวนตัวอักษรใต้ช่องกรอก |

กฎเหล่านี้อยู่ใน `Profile` ไม่ใช่ใน View เพื่อให้ทดสอบได้โดยไม่ต้องผ่าน UI

การนับความยาวใช้จำนวน `Character` ของ Swift ไม่ใช่จำนวน byte เพื่อให้ภาษาไทยและ emoji นับได้ตรงกับที่ผู้ใช้เห็น

## การเก็บข้อมูล

ไฟล์ JSON ชื่อ `profile.json` วางใน Application Support directory ของแอป

เลือกที่นี่แทน Documents เพราะเป็นข้อมูลที่แอปจัดการเอง ผู้ใช้ไม่ได้เปิดดูโดยตรง
และเลือกไฟล์แทน `UserDefaults` เพราะนี่คือเนื้อหาของผู้ใช้ ไม่ใช่การตั้งค่า

`ProfileStore` เป็น `@Observable` class:

- `var profile: Profile` — state ปัจจุบัน อ่านโดย View
- `save() throws` — เขียนลงดิสก์

การอ่านเกิดขึ้นแบบ synchronous ตอนสร้าง store ใน `null_appApp` โดยตั้งใจ
ไฟล์มีขนาดไม่กี่ร้อย byte การอ่านจึงเร็วกว่าหนึ่งเฟรม และการทำแบบ async จะทำให้เห็นจอว่างแวบหนึ่ง
ก่อนข้อมูลจะมา ซึ่งแย่กว่าการรอเสี้ยววินาที

ส่วน `save()` เป็นจุดที่อาจช้าได้หากดิสก์ติด จึงให้งานเขียนไฟล์จริงเป็น `nonisolated`
แล้วรอผลด้วย `await` ตัว store เองเป็น main-actor ตาม `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`
ของโปรเจกต์ ซึ่งถูกต้องแล้วสำหรับ state ที่ผูกกับ UI

เพื่อให้ทดสอบได้ `ProfileStore` ต้องรับ path ของไฟล์เข้ามาทาง initializer โดยมีค่าเริ่มต้นเป็น
Application Support จะได้ชี้ไปที่ temporary directory ตอนเขียน test ได้

## Flow การแก้ไข

ใช้ draft copy ไม่ใช่ผูก binding ตรงกับ store:

1. กด Edit → `ProfileView` ส่งค่า `Profile` ปัจจุบันเข้าไปใน sheet
2. `ProfileEditView` เก็บเป็น `@State` ของตัวเอง ผู้ใช้แก้บน copy นี้ — store ยังไม่เปลี่ยน
3. กด Save → `ProfileEditView` ส่ง `Profile` ที่แก้แล้วออกมาทาง closure แล้วปิด sheet
4. `ProfileView` รับค่า เขียนเข้า store แล้วสั่ง save ลงดิสก์
5. กด Cancel → ปิด sheet เฉย ๆ ไม่เรียก closure

`ProfileEditView` จึงไม่รู้จัก `ProfileStore` เลย มันรับ `Profile` เข้ามาหนึ่งตัวและส่งออกไปหนึ่งตัว
ทำให้ preview และ test ได้โดยไม่ต้องเตรียม store และทำให้ทุกการเขียนดิสก์เกิดที่เดียวคือ `ProfileView`
ซึ่งเป็นที่เดียวกับที่แสดง alert ตอนบันทึกพลาด

เหตุผลที่ใช้ draft: ถ้าผูก binding ตรง ผู้ใช้จะยกเลิกไม่ได้เลยเพราะทุกตัวอักษรถูกบันทึกทันที
และจะไม่มีจังหวะให้ validate ก่อนบันทึก

## การจัดการ error

| สถานการณ์ | พฤติกรรม |
|---|---|
| เปิดแอปครั้งแรก ยังไม่มีไฟล์ | ถือเป็นเรื่องปกติ ไม่ใช่ error — ใช้ `Profile` ค่าว่าง |
| ไฟล์มีอยู่แต่ decode ไม่ผ่าน | ใช้ `Profile` ค่าว่างแทน ไม่ crash ไม่รบกวนผู้ใช้ |
| เขียนไฟล์ไม่สำเร็จ | แสดง alert บนหน้า Profile แต่ยังเก็บค่าใน memory ไว้ ผู้ใช้ไม่เสียสิ่งที่พิมพ์ |

การเขียนไฟล์ใช้ `.atomic` เพื่อไม่ให้ไฟล์เสียหากถูกขัดจังหวะกลางคัน

`load()` ไม่ throw ออกไปหา UI เลย ทุกความล้มเหลวของการอ่านแปลงเป็นค่าเริ่มต้น
ส่วน `save()` throw เพราะผู้ใช้ต้องรู้ว่างานที่เพิ่งกดบันทึกไม่สำเร็จ

## เรื่องแพลตฟอร์ม

เป้าหมายเดียวส่งได้ 4 แพลตฟอร์ม จึงต้องระวัง:

- `NavigationStack` ใช้ได้ทุกแพลตฟอร์ม ไม่ต้องแยกโค้ด
- sheet บน macOS ไม่มีขนาดเริ่มต้นที่เหมาะสม ต้องกำหนดขนาดขั้นต่ำให้ `ProfileEditView`
  ไม่งั้นฟอร์มจะถูกบีบจนใช้งานไม่ได้
- ระยะห่างและขนาดตัวอักษรใช้ค่ามาตรฐานของ SwiftUI ไม่ hard-code ตัวเลขที่อิงกับ iPhone

## Test

โปรเจกต์ยังไม่มี test target และการเพิ่ม target ใหม่ต้องแก้ `project.pbxproj`
ซึ่ง `CLAUDE.md` ระบุไว้ว่าเสี่ยงทำโปรเจกต์เสียหาย จึงไม่ทำในรอบนี้

แนวทางที่ใช้แทน: **ออกแบบให้ทดสอบได้ แต่ยังไม่เขียน test**

logic ที่มีเนื้อทั้งหมดถูกวางไว้ใน type ที่ไม่ผูกกับ SwiftUI และไม่แตะ global state:

- กฎอักษรย่อ และกฎ validation อยู่ใน `Profile` ซึ่งเป็น struct ล้วน
- `ProfileStore` รับ path เข้ามาได้ จึงชี้ไปที่ temporary directory ได้

เมื่อผู้ใช้เพิ่ม test target ผ่าน Xcode แล้ว จะเขียน test ครอบสิ่งเหล่านี้ได้ทันทีโดยไม่ต้องแก้โค้ดเดิม
กรณีที่ควรทดสอบก่อนเป็นอันดับแรก: การสร้างอักษรย่อจากชื่อรูปแบบต่าง ๆ, การ validate ความยาว,
และการ save แล้ว load กลับมาได้ค่าเดิม

## การเปลี่ยนแปลงหลังส่งมอบ

**2026-08-12 — เปลี่ยน navigation เป็น TabBar**

เดิม `HomeView` มีปุ่ม "View Profile" ที่ push ไปหน้า Profile ตามที่อธิบายไว้ข้างบน
ตอนนี้เปลี่ยนเป็น `TabView` สองแท็บแทน ผู้ใช้สลับระหว่าง Home กับ Profile ได้โดยตรง

สิ่งที่เปลี่ยนจริง:

- `null_appApp.swift` — `NavigationStack { HomeView }` กลายเป็น `TabView` ที่มีสองแท็บ
  และ **`NavigationStack` ย้ายไปอยู่ข้างในแต่ละแท็บ** ไม่ใช่ครอบ `TabView`
  เพื่อให้แต่ละแท็บมี navigation history และ toolbar ของตัวเอง
  ถ้าเอา `NavigationStack` ครอบ `TabView` แทน ปุ่ม Edit ของหน้า Profile จะไปโผล่ตอนอยู่แท็บ Home ด้วย
- `HomeView.swift` — ลบปุ่ม "View Profile" ออก เพราะซ้ำกับแท็บ หน้า Home จึงว่างจริง ๆ แล้ว
- ใช้ `.tabViewStyle(.sidebarAdaptable)` เพื่อให้ iPhone ได้ tab bar ล่างจอ
  ส่วน iPad, macOS และ visionOS กลายเป็น sidebar ซึ่งเป็นสำนวนของแต่ละแพลตฟอร์ม โดยไม่ต้องเขียน `#if os(...)`

ส่วนที่เหลือของ spec นี้ยังถูกต้องทั้งหมด — `Profile`, `ProfileStore`, flow การแก้ไข,
validation และการจัดการ error ไม่ถูกแตะเลย ไฟล์ที่ shipped อยู่ใต้ `null-app/` เป็นตัวจริงเสมอ

**2026-08-12 — เพิ่ม username แบบมี suffix ถาวร**

`Profile` มีฟิลด์ใหม่ `usernameSuffix` และ computed `username` ที่ประกอบเป็น `@purintae-K7M4XQ`

- **ส่วนหน้า** มาจากชื่อ ตัดเหลือแต่ a-z0-9 เปลี่ยนตามชื่อเสมอ ถ้าไม่เหลืออักษรใดเลยใช้ `user`
- **ส่วนท้าย** สุ่มครั้งเดียวตอนโหลดโปรไฟล์ที่ยังไม่มี แล้วไม่เปลี่ยนอีกเลย

เหตุผลที่ทำแบบนี้: ความไม่ซ้ำของ username เป็นคุณสมบัติระดับ "ทุกคนในระบบ" ซึ่งแอปที่เก็บข้อมูล
ในเครื่องล้วนรับประกันไม่ได้ suffix สุ่มเปลี่ยนโจทย์จากการ *รับประกัน* เป็น *ความน่าจะเป็น*
ที่ต่ำจนไม่ต้องแคร์ — วิธีคิดเดียวกับ UUID

ชุดอักษรของ suffix มี 32 ตัว โดยตัด `I` `O` `0` `1` ออกเพราะแยกกันไม่ออกเวลาอ่านออกเสียงหรือพิมพ์ตาม
ยาว 6 ตัว จึงมี 1,073,741,824 แบบ

**ช่องชื่อถูกจำกัดเป็นอักษรอังกฤษ** — `a-z A-Z 0-9` ช่องว่าง `-` และ `'` เท่านั้น
พิมพ์อย่างอื่นแล้วจะขึ้นข้อความเตือนและปุ่ม Save ถูกปิด เลือกวิธีนี้แทนการลบตัวอักษรทิ้งเงียบ ๆ
เพราะการพิมพ์แล้วจอไม่ขึ้นอะไรทำให้ผู้ใช้นึกว่าคีย์บอร์ดพัง

ผลข้างเคียงที่ยอมรับ: ชื่อที่มีอักษรมีสระบนอย่าง "José" ก็ถูกปฏิเสธด้วย ไม่ใช่แค่ภาษาไทย

`ProfileStore` สุ่ม suffix ให้ตอนโหลดถ้ายังไม่มี **แล้วเขียนลงดิสก์ทันที** ไม่รอผู้ใช้กด Save
เพราะถ้ารอ การปิดแอปก่อนบันทึกจะทำให้สุ่มใหม่ทุกครั้ง username ก็จะไม่นิ่ง
ซึ่งขัดกับเหตุผลทั้งหมดที่มี suffix

ไฟล์เดิมที่บันทึกไว้ก่อนหน้านี้ไม่มี key `usernameSuffix` แต่ decoder ที่ทนต่อ key ที่หายไป
(เพิ่มไว้ก่อนหน้านี้) ทำให้อ่านผ่านและได้ค่าว่าง แล้ว store ก็เติมให้เอง ข้อมูลเดิมไม่หาย

**2026-08-12 — หน้า Profile เป็น layout แบบ Twitter**

จากเดิมที่เป็นวงกลม ชื่อ bio เรียงกลางจอ เปลี่ยนเป็น banner เต็มความกว้าง + avatar เกยขอบล่างชิดซ้าย
+ ปุ่ม Edit ทางขวา + ชื่อ handle bio และวันที่เข้าร่วม เรียงชิดซ้าย

- `ProfileHeader.swift` เป็นไฟล์ใหม่ รับ `Profile` เข้าไปอ่านและคืนเจตนาออกมาทาง closure
  จึงไม่รู้จัก `ProfileStore` และ preview ได้โดยไม่ต้องเตรียมอะไร เหมือน `ProfileEditView`
- ปุ่ม Edit ย้ายจาก toolbar ลงมาอยู่แถวเดียวกับ avatar ตามสำนวนของ layout นี้
  และเอาปุ่มบน toolbar ออกเพื่อไม่ให้มีปุ่มเดียวกันสองที่
- `InitialsAvatar` รับ `tint` เข้ามาได้แล้ว และเปลี่ยนพื้นเป็นทึบแสง
  เพราะต้องวางทับ banner สี ถ้าพื้นโปร่งจะเห็นสีทะลุขึ้นมา

**สีประจำโปรไฟล์** คำนวณจาก `usernameSuffix` ด้วย djb2 hash แล้วแปลงเป็น hue
suffix ถาวรอยู่แล้ว สีจึงถาวรตามไปด้วยโดยไม่ต้องเก็บข้อมูลเพิ่ม แก้ปัญหา "ไม่มีรูปปก"
โดยไม่ต้องใส่รูป placeholder ที่ดูปลอม `Profile` คืนแค่ค่า hue ไม่ import SwiftUI

**`createdAt`** เป็นฟิลด์ใหม่ ตั้งครั้งเดียวพร้อม suffix เป็น optional เพราะไฟล์เก่าไม่มีค่านี้จริง ๆ
View ซ่อนบรรทัดวันที่เมื่อเป็น nil แทนการเดาวันแล้วแสดงข้อมูลที่ไม่จริง
`ProfileStore` ตรวจ suffix กับ createdAt แยกกัน เพราะไฟล์ที่บันทึกระหว่างทางอาจมีอย่างแรกแล้วแต่ยังไม่มีอย่างหลัง

วันที่เก็บเป็น ISO8601 แทนตัวเลข timestamp เพื่อให้เปิดไฟล์อ่านเองแล้วเข้าใจได้
encoder กับ decoder ต้องตั้งกลยุทธ์เดียวกันเสมอ

**ใต้วันที่เข้าร่วมจบเลย** ไม่ใส่แท็บปลอมหรือข้อความบอกว่าว่างเปล่า เพราะแอปยังไม่มีแนวคิดเรื่องโพสต์
การประกาศว่าไม่มีอะไร แย่กว่าการจบให้สนิท

**2026-08-12 — cover ชนขอบบนของจอ**

ซ่อน navigation bar บนหน้า Profile แล้วให้ ScrollView ปล่อย safe area ด้านบน
cover จึงไหลขึ้นไปทับ status bar ได้จริง

จุดที่พลาดง่าย: `.ignoresSafeArea` ต้องอยู่บน `ScrollView` ไม่ใช่บนตัวสี banner
เพราะ ScrollView เป็นตัวที่กัน safe area ไว้ ใส่ผิดที่แล้วจะไม่มีผลอะไรเลยและดูเหมือนโค้ดถูก

ไม่เสียการนำทางจากการซ่อนแถบบน เพราะหน้านี้เป็นรากของแท็บ ไม่เคยมีปุ่มย้อนกลับ
และแท็บด้านล่างก็บอกอยู่แล้วว่าอยู่หน้าไหน

**เรื่องปีพุทธศักราช** — `Date.formatted()` เคารพปฏิทินตาม locale ของเครื่อง
เครื่องที่ตั้งภูมิภาคเป็นไทยจึงแสดง "Joined August 2569 BE" ปนกับ UI ภาษาอังกฤษ
ตัดสินใจแล้วว่า **ปล่อยไว้ตามนี้** เพราะเป็นพฤติกรรมที่ถูกต้อง และจะเข้าที่เองเมื่อทำ localization
อย่าไปบังคับเป็นปฏิทินเกรกอเรียน — นั่นคือการเขียนทับค่าที่ผู้ใช้ตั้งไว้เอง
